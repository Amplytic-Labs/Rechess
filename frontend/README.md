# Rechess — Frontend (Expo / React Native mobile app)

Expo SDK 58 · React Native 0.88 · React 19.3 · TypeScript (strict) ·
Expo Router · uniwind 1.14 (Tailwind CSS v4) · HeroUI Native 1.1 ·
Reanimated 4.7 · zustand 5

> **Read [`RULES.md`](./RULES.md) before writing any code — it is binding
> for humans and AI assistants.** Then read your module's README (§ module
> map below).

## Run it

```bash
cd frontend
npm install        # once — deps are already committed in package-lock.json
npm start          # Expo dev server → scan the QR with Expo Go on your phone
```

- Simulator: `npm run ios` (needs macOS) / `npm run android`.
- Quick UI check without a device: `npm run web` (dev convenience only —
  the product is the mobile app).
- Point the app at the backend: F3's `src/services/README.md` documents the
  connection URL (LAN IP for dev, WSS in deployment).

## Quality gates — run before every push

```bash
npm run typecheck  # tsc --noEmit
npm run lint       # eslint (flat config; enforces RULES.md)
```

Plus your module's **manual test checklist** (RULES.md §5 — the frontend
has no unit-test runner by design; each module README lists its manual
steps). CI (B4's workflow) runs the same gates. The wire protocol itself is
verified on the backend (`cargo test`) against the exact same fixtures.

## What is preconfigured (don't redo it)

- Expo Router with `src/app/_layout.tsx`: `GestureHandlerRootView`,
  `SafeAreaProvider`, `HeroUINativeProvider`, `Stack`, splash handling.
- **uniwind + Tailwind CSS v4**: `global.css` (all semantic tokens incl.
  board colors, light/dark), `metro.config.js` (`withUniwindConfig`),
  generated `src/uniwind-types.d.ts` (className types — regenerated by
  `expo start`/`expo export`, committed). No `tailwind.config.js`, no babel
  config, no ThemeProvider — dark mode follows the system automatically.
- **HeroUI Native**: installed with all mandatory peers (`react-native-svg`,
  `tailwind-variants`, `tailwind-merge`). Use its components for standard
  controls — always granular imports (`heroui-native/button`).
- Third-party `className` interop: `src/components/common/styled.ts`
  (`withUniwind` wrappers; extend it, don't scatter wraps).
- ESLint flat config (`eslint.config.js`) enforcing RULES.md: no StyleSheet,
  no expo-status-bar, no react-navigation, no nativewind, no root
  heroui-native imports, no inline styles/color literals.
- Prettier with `prettier-plugin-tailwindcss` (className sorting, wired to
  `global.css` via `tailwindStylesheet`) — run `npx prettier -w .`.

## Stack notes

- Status bar: configured app-wide in `app.json`
  (`userInterfaceStyle: "automatic"`); mounting `expo-status-bar` in code is
  **banned** (RULES.md §1.2).
- New Architecture / edge-to-edge are enforced by SDK 58 — do not fight them.
- Versions are pinned in `package.json` + `package-lock.json`; adding a
  dependency is a team decision (RULES.md §2).
